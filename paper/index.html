Predicting Content Performance Decline from Search Intelligence Signals

A client-held-out machine learning analysis of whether current-month search performance signals can help identify content likely to experience an impressions decline in the following month.

Abdalla Mohamed
Google Search Ranking & Discoverability Capstone

Abstract

This study asks whether current-month search performance signals can help identify content likely to experience a meaningful impressions decline in the following month. A monthly content-level dataset was constructed from the FlyRank search warehouse using impressions, clicks, CTR, average position, scroll events, and AI-session activity as predictive features. A Random Forest was evaluated using a client-grouped holdout in which 52 clients were used for training and 14 unseen clients were reserved for testing. The model achieved 60.28% accuracy, 49.42% precision, 61.17% recall, and a 54.67% F1 score, while a simple always-decline baseline achieved 39.16% accuracy and 56.28% F1. The results provide directional evidence that the measured signals contain useful predictive information, but the model should be treated as decision support rather than proof of causality or Google's ranking mechanism.

Introduction / Problem Statement

Content teams need a practical way to prioritize pages for review when search visibility may be weakening. Reviewing every page equally is inefficient, so this project investigates whether observable search performance signals can be used to rank content for review.

The research question is:

Can current-month search performance signals identify content that is likely to experience an impressions decline in the following month?

The intended output is not an automated decision maker. It is a prioritization signal that can support content monitoring and review.

Data

The analysis uses the full FlyRank warehouse release and its daily content-performance data. The available release contains 78,835,655 rows, 70 clients, and 427,292 content records spanning January 27, 2025 through June 30, 2026.

The modeling data was aggregated to monthly content-level observations, producing 1,329,512 modeling rows across 66 clients and 288,308 content records.

The model uses current-month impressions, clicks, CTR, average position, scroll events, and AI-session activity. The next month's impressions are used only to construct the outcome label.

Client and content identifiers are anonymized. No client names, domains, URLs, private queries, credentials, or raw exports are exposed in this paper.

Methodology

Target definition

The target represents a meaningful decline in impressions from the current month to the following month. An observation is labeled as a decline when the following month's impressions are at most 70% of the current month's impressions.

Validation design

A client-grouped train/test split was used. The training set contains 1,124,959 rows from 52 clients, while the test set contains 204,553 rows from 14 clients. No client appears in both sets.

This design evaluates whether the model can generalize to clients that were not present during training. The same split was used for the baseline and Random Forest.

Model

A Random Forest classifier was trained with 100 trees, a maximum depth of 12, a fixed random seed, parallel processing, and balanced class weights.

Leakage audit

The model feature list was explicitly checked against the future outcome and target columns. Neither next_month_impressions nor decline_label was present among the model features. The leakage audit returned PASS.

Results

The Random Forest produced measured predictive signal on the client-held-out test set. However, it did not outperform the simple baseline on every metric.

False positives had an average position of 23.67, while false negatives had an average position of 17.10. These aggregate error results show that the classifier can both flag content that does not subsequently meet the decline definition and miss some genuine declines.

The errors reinforce the role of the model as a review-prioritization tool rather than a definitive classifier.

Limitations & Honest Framing

Predictive, not causal

The analysis measures predictive associations. It does not establish that any signal causes a future impressions decline.

Client-based validation

The evaluation holds out clients rather than simulating a future time period. It therefore tests generalization to unseen clients.

Feature coverage

Many factors that may influence future search performance are not represented by the selected features.

Baseline trade-off

The baseline achieved higher recall and slightly higher F1, so the Random Forest is not universally better.

Safe framing: The findings are observed and measured signals that can support content-review decisions. They should not be presented as proof of Google's ranking algorithm or causal refresh impact.

Ranked Action Recommendations

The following action playbook ranks practical review priorities based on the measured feature importance and error analysis. These are decision-support recommendations, not a ranked list of individual pages or proof that any signal causes decline.

1

Review weaker average-position signals

Average position was the most important feature in the fitted model. Content showing weaker search positions can be prioritized for review and monitoring.

2

Prioritize visible content showing deterioration

Impressions were the second most important feature. Content with meaningful existing visibility can be useful candidates for proactive review.

3

Investigate CTR opportunities

CTR represented a substantial share of model importance. Visible content with weaker click-through performance can be reviewed for metadata, search-intent alignment, and content presentation.

4

Monitor click-volume changes

Clicks provided additional predictive information beyond impressions and CTR. Click changes should be interpreted together with visibility and position.

5

Use engagement as supporting evidence

Scroll events contributed to the model but were less important than the main search-performance signals, making them more appropriate as secondary evidence.

6

Monitor AI-session activity cautiously

AI-session activity had very low feature importance in this model and should therefore not drive prioritization on its own.
